What type is my data?

16:20
Type Example In R
Number 41 TWh numeric
Text “Drax” character
Category coal, gas, wind factor
Ranked category clay < silt < sand < gravel ordered factor

  • [16:20–16:24] New concept before the walkthrough: the type of a column, not just its values. Students hit this in Exercise 1’s extension (legend order) and Exercise 3 (reorder()).

  • Anticipated code:

    grains <- c("sand", "clay", "gravel", "silt", "sand")
sort(grains)
#> "clay" "gravel" "sand" "sand" "silt"

grains <- factor(grains, levels = c("clay", "silt", "sand", "gravel"))
sort(grains)
#> clay silt sand sand gravel

grains <- factor(grains, levels = c("clay", "silt", "sand", "gravel"),
                 ordered = TRUE)
grains[1] > grains[4]
#> TRUE

  • Ask before running sort(): “What order will R give?” Alphabetical puts gravel between clay and sand. No geologist would.

  • levels fixes the order; ordered = TRUE adds the ranking, so > works. Without it, grains[1] > grains[4] gives NA and a warning.

  • Fuel is a plain factor, not an ordered one: gas isn’t “more” than coal. We still choose the order, so the legend reads sensibly. That’s step 3 of the walkthrough.

  • From Python: this is pandas Categorical(..., ordered=True).

Text sorts alphabetically; you define how a factor sorts.

The anatomy of a good figure

16:30

  • This is Exercise 1 for the students - unleash them! But - they are going to need showing pivot_longer().

  • Plot one fuel with geom_line() first, hit the wall of needing a second geom_ per fuel, then reshape. The reshape earns its place that way.

  • Anticipated code (Exercise 1’s solution on the exercise page, plus the factor() step, which previews the extension’s question 2):

    elec <- read.csv("data/uk_electricity.csv")

elec_long <- pivot_longer(
  elec,
  cols = c(coal_twh, gas_twh, wind_twh, bioenergy_twh),
  names_to = "fuel",
  values_to = "twh"
)

elec_long$fuel <- factor(
  elec_long$fuel,
  levels = c("gas_twh", "wind_twh", "bioenergy_twh", "coal_twh")
)

ggplot(elec_long, aes(x = year, y = twh, colour = fuel_f)) +
  geom_line() +
  labs(
    x = "Year",
    y = "Generation (TWh)",
    colour = "Fuel type",
    caption = "Source: DUKES 2026"
  )

  • Show the completed plot. Ask: “What’s the story here?” Students should see biomass rising as coal falls.

Every figure should have a “so what” — what should the reader take from it?

Stuck? Find the layer

16:48

Data → Aesthetics → Geometry: ggplot(data, aes(...)) + geom_*()

If your plot… Turn to… For example
has the wrong rows, or the wrong shape (one column per fuel) Data: fix it before ggplot() pivot_longer(), factor(), a new column
shows the wrong column, or no colour or legend Aesthetics: which column drives which channel aes(x = …, y = …, colour = …)
draws the wrong kind of mark Geometry: the mark that shows those channels geom_line(), geom_col(), geom_point()

Labels, axis ranges and themes come last: labs(), coord_cartesian(), theme_*().

  • [2 min, within 16:35–17:25] A refresher of the grammar from the content session, recast as “where do I look when it goes wrong?”. Leave it up while students work.
  • Most stuck plots are a data problem dressed as a ggplot problem. Try to fix the plot’s shape in geom_*() and you’ll go round in circles.
  • Per exercise:
    • Ex 1: four fuels in four columns is a data problem: pivot_longer(), then colour = fuel in aes().
    • Ex 2: bars are a geometry choice: geom_col() for heights already in the data, not geom_bar(), which counts rows.
    • Ex 3: bar order is decided in the data (reorder() inside aes() is the shortcut).
    • Ex 4: the percentage is a new column, computed in the data before ggplot() ever sees it.
  • When a student is stuck, ask “which layer is wrong?” before you look at their code.

  • [17:00–17:10, inside 16:35–17:25] Interrupt the exercises. Do this live, slowly, narrating every click. Confident students may keep working; everyone else saves along with you.
  • Export: the file is named after the page, so Week 2 gives week2.R. It goes to Downloads, not the repo.
  • File extensions: Windows hides them by default. File Explorer → View → Show → File name extensions. On a Mac: Finder → Settings → Advanced → Show all filename extensions.
  • What an extension does: it’s part of the file name that tells the operating system (and you) what kind of file it is, and so which program opens it. .R is plain text that R can run; .csv is a table; .md is Markdown, which their briefing will be; .png an image.
  • Renaming the extension doesn’t convert the file: week2.R.txt is still R code, but nothing treats it as R. If the extension is hidden, renaming week2 to week2.R can produce exactly that.
  • Move the file into the repo folder (the one GitHub Desktop cloned in Week 1). Replace last week’s file? No: week2.R is a new file beside week1.R.
  • GitHub Desktop lists week2.R as new. Show the diff, write a commit message that says what was done (“Trend and import plots”), commit, push. Committing loads the van; pushing sends it to the depot.
  • Open the repo on GitHub.com and click into week2.R.
